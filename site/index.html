The question it answers

Not “who has the highest average fantasy score.”

Given my exact league rules, roster, opponents, available players, schedule, current NBA roles, and recent basketball context — what decision gives my team the highest expected value?

Three principles

Each one is the reason a specific piece of the architecture looks the way it does.

Statistics are necessary but not sufficient

A player can post elite numbers and then walk into a trade, a new primary facilitator, or a minutes restriction. The engine keeps quantitative production and structured context events as parallel evidence, and never lets the second overwrite the first — a projection always shows baseline, adjustment, and final as three separate numbers.

No data provider is load-bearing

The domain never learns whether a value came from an API, an HTML scrape, a CSV, or a human typing it in. Manual entry always works, so a dead integration lowers confidence and surfaces staleness rather than breaking the app.

The statistics make the recommendation

A language model may propose a context event from a news article for a human to review. It gets no tools, a schema-constrained output, and no path to a recommendation. The worst outcome of a successful prompt injection is a rejected proposal in a review queue.

The specification is the artifact

Written before the code, not after it — so a new contributor or an agent can build a subsystem correctly without asking anyone.

  • Every invariant names its own check. A rule paired with a test row, a scan, or a validator assertion. Rules that are only prose are listed as knowingly unenforced rather than presented as guarantees.
  • Every canonical value lives in exactly one file. Stat keys, formulas, thresholds, enum members, weight constants. Everything else links to it, because duplication is where drift starts.
  • Status is promoted only by evidence. planned → partial → implemented requires code and passing tests in the same commit. Documentation never promotes a status.
  • The bundle validates itself. A stdlib-only checker verifies frontmatter, status values, dependency resolution, and every internal link — and runs before any dependency is installed.

Specification defects caught before the code existed

Seven so far. A cold read of a spec is dramatically cheaper than discovering these in a debugger.

DefectResolution
Rolling 7/14/30-day windows were required, but the only source for per-game data is a robots.txt-disallowed path Season pages for the MVP; per-game data via the permitted /boxscores/ route as a rate-limited background import (~3.5h per season) rather than an interactive request
The draft formula added projected value, value-above-replacement, and the context adjustment — counting the same production up to three times Addends separated from display-only decomposition fields; roster fit redefined to measure redundancy alone
The streaming score multiplied a summed per-day value by the count of usable days Value is a sum across usable days; the count is reported to the user, never a multiplier on it
Category z-scores on raw percentages make a 2-for-2 free-throw shooter a maximal asset Volume-weighted impact form, pinned by a required test asserting exactly that player scores near zero
“How many categories can you punt” was a matter of taste It is derivable: winning 9 categories needs 5, so punting k is feasible only while k ≤ 4. Ceiling set at 3 for margin
Adding survival probability alongside the ADP proxy would have counted “the market says wait” twice Opportunity cost replaces the market term; both contract and code change in one commit
“Supports category leagues” meant either scoring configuration or a full z-score analyzer Split explicitly — two competent implementers would otherwise have built different products

Data sources & compliance

Scraping is a controlled infrastructure capability, not ad-hoc HTML parsing.

RoleSourceMethod
Players, teams, scheduleballdontlieDocumented HTTP API, free tier
Season statisticsBasketball-ReferenceHTML scrape, season pages only
Average draft positionFantasyProsHTML scrape, plus CSV and manual entry
League rules & rostersManual, CSV, YahooESPN is CSV / manual only — never an authenticated scrape

A per-host allowlist records exact permitted paths, disallowed patterns, crawl delays, and the date each host’s robots directives were last verified. The self-imposed ceiling is 6 requests per minute — far below every host’s threshold, because the cost of being slow is nothing and the cost of a ban is losing the data source during draft season.

Terms-of-use compliance is a human judgment and stays the operator’s responsibility — it is a line item on the release checklist rather than something the code pretends to guarantee.
